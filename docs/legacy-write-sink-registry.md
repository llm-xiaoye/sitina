# Legacy write-sink registry

The Phase -1 registry is generated by the versioned
`PYTHON_AST_LEGACY_SINKS_V1` scanner and verified with a process audit hook in a
disposable Sitina home. It covers SQLite connections/statements, JSONL append,
mutable JSON, checkpoints, run manifests, replay snapshots, evidence exports,
Blackboard, handoff/lease/side-effect state, filesystem mutation, maintenance,
tool/MCP execution, provider/network access, and external processes.

Classifications are:

- `READ_ONLY*`: no Phase 0 writer fence is required.
- `LEGACY_MUTATION_REQUIRES_PHASE0_FENCE`: a known mutation entrypoint that
  Phase 0 must guard at both the top-level route and low-level sink.
- `LEGACY_EXTERNAL_REQUIRES_PHASE0_FENCE`: provider/tool/process/publication
  boundary requiring the same authority and effect fence.
- `UNKNOWN*`: a Phase -1 blocker. Acceptance requires this count to be zero.

The machine-readable inventory, including exact file, function, line, source
expression, category, and hash, is written to
`~/Desktop/sitina/output/sitina-bplus-write-sink-inventory.json`.
Production files are not instrumented or changed by this scan.

The accepted Phase -1 scan found 248 sink expressions: 202 known Legacy
mutations, 21 known external boundaries, and 25 read-only operations. Parse
errors and unknown dynamic entrypoints are both zero. Inventory identity:
`sha256:43abc89182e9be195bf6172d63534f82deabd7997625d5f963d2dfa27adab10b`.

## Phase 0 fence coverage

The final Phase -1 source binding contained 249 expressions (202 mutations, 21
external boundaries, 26 read-only operations) with no unknown or parse error.
After adding Phase 0 control-plane code, the same scanner reports 290 expressions:
229 mutations, 21 external boundaries, and 40 read-only operations. Its identity
is `sha256:92ad6b47ad9b20384139f276dd80973b43be1b2cb30870b13379ca5d8fa6af72`.

`LEGACY_FENCE_COVERAGE_V1` binds every one of those 290 expressions to a guard:

- 229 filesystem/SQLite mutations use the package audit hook plus a kernel
  shared writer lease;
- 21 provider/process/network boundaries are denied while frozen and retain
  their existing top-level policy gates;
- 40 read-only expressions require no writer lease;
- blocker count is zero.

Coverage identity is
`sha256:8aa5c0a768b06fe91dce6eb3a2fed0c1a2c2155221c9ae807c21018561e0625b`.
The audit hook is an application guard, not an OS sandbox. Kernel `flock`
coordinates writers/freezer; it does not sandbox arbitrary child processes.
