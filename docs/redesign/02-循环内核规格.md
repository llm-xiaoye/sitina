## 一、复用基础与改造范围

现有 `extensions/runtime.py` 的 `AutonomousRuntime` 已将 assistant/tool 消息回灌循环；正式 Forge 路径会使用它，执行桥还存在有限验证和返工。应复用这些真实能力，不能把整个执行链描述成“零回边”。

现有内嵌循环的非空最终文本可直接产生成功结果，仍有默认总轮数限制，任务开始时固定 Skill 和工具 schema。新内核需要任务级状态、按类型验收、能力刷新、长期上下文、持久输入、后台生命周期和恢复。已有存储 checkpoint 并不能单独完成这些接线。

## 二、Loop 的责任顺序

以下是责任顺序，不是要求模型每轮按固定角色管线调用：

```text
1. 后台接收并持久化输入，读取当前任务投影与运行身份。
2. 处理纠偏、暂停、取消；核对旧操作是否仍在运行或效果未知。
3. 需要等待时关联具体操作或问题，让出模型调用，任务保持可恢复。
4. 按任务依赖及本任务明确的安装／更新切换完整能力快照，构建有界上下文。
5. 主助手结合证据选择执行、调查、只读子任务、检查、完成提案或询问。
6. 产生业务写入的操作先取得业务修改通道和资源；只读操作按读取合同执行，不占用该通道。所有操作都复核任务／执行身份、当前输入及适用版本；写入操作获权后还要最后核对资源前提。随后先持久登记操作身份、执行段版本和恢复策略，确认写前意图可读回后才实际执行。
7. 保存原始结果；主助手解释与验收目标的关系，更新义务和进展依据。
8. 有缺口则继续；完成提案进入当前版本的程序检查和必要独立评审。
9. 成功提交前再次核对目标、验收、成果、执行身份和已处理输入位置。
10. 提交终态与可恢复的交付/整理义务；用户成果交付不等待语义提取。
```

工具结果、检查缺口和子任务反馈都返回原任务；没有 tool_calls 不自动意味着完成。等待时不反复调用模型制造无意义轮次。

## 三、任务状态与输入

| 状态或事件 | 行为与恢复条件 |
|---|---|
| 可执行 | 当前要求未完成且下一步可做，继续循环。 |
| 等待操作 | 保存操作编号、归属、输出位置和完成事件；结果到达后继续。 |
| 等待评审 | 保留待审版本；评审不可用不能自动改为主助手自评通过。 |
| 等待用户 | 保存已完成部分、问题和恢复入口；收到回答后核对有效目标。 |
| 卡住 | 同一障碍四次有效尝试无进展；保留尝试与证据，等待新信息或方向。 |
| 暂停 | 不派发新动作，按操作合同处理已运行任务；明确继续后恢复。 |
| 取消 | 不继续推进，处理可取消操作；已经发生的效果保留，不假称回滚。 |
| 最终失败 | 记录不可恢复原因、部分成果、未完成义务和结项整理义务。 |
| 成功 | 程序确认当前要求、必要评审、成果与交付均满足，提交 `SUCCEEDED`。 |

熔断是原因，不替代上述状态；旧 `INTERRUPTED` 不再泛指所有输入。暂停、等待和卡住不是成功，也不应被强制归为最终失败。

原始请求不可改写；活动任务的有效目标和约束可以版本化更新。状态询问不改目标。完成后追加工作创建关联新任务，沿用有用背景，旧 episode 保持关闭。

任何必要询问都包含已完成部分、明确阻碍、推荐、推荐原因、每个选项利弊及恢复方式。已授权范围内的普通操作不重复询问。

## 四、完成门与验收责任

主助手提交当前成果、逐项依据和剩余义务，只能提议完成。程序检查当前有效要求、证据适用性和未完成操作；修改、安装等任务在交付前由一个非主循环模型独立只读评审。

| 类型 | 必要完成依据 |
|---|---|
| 修改代码 | 要求的行为、相关实际检查、符合范围的改动及必要评审。 |
| 只读调查或审查 | 问题得到回答，来源可核实，未确定内容明确。 |
| 文档或图形成果 | 实际制品满足内容和格式要求；按需要读回或检查呈现。 |
| 安装能力 | 实际位置完成部署，消费者加载并使用正确版本，当前任务和新会话满足用例。 |
| 已经满足要求 | 核实无需修改的依据，不能强行生成无意义 diff。 |
| 需要用户信息 | 正确进入等待；案例可评价询问正确，但任务本身未完成。 |

**没有统一 diff 非空或必须跑测试的门槛。** 适用代码检查记录真实命令、环境、退出码、收集/执行数量和原始输出；退出码本身不能证明语义完成。安装成果可能在扩展目录、依赖环境和配置中，项目 diff 不能替代实际使用验证。

### 检查与评审结果

- 程序可直接判定的数据失败不能被模型投票改为成功。主助手和评审不得为过门降低用户必需要求。
- 评审取得当前用户要求、验收条目、实际成果、原始证据和未处理事项，不仅阅读主助手摘要。
- 返回无阻断、必须修项、证据不足或可选建议。必须修项关联当前目标和具体证据；风格偏好和额外功能不扩大任务。
- 评审可读取、搜索并请求程序执行检查。临时缓存和输出由检查合同安排；任意 shell、进程、MCP 或外部写入不会因“用于验证”而成为只读。
- 相同评审分歧反复三次，保存并集中报告；这是独立计数。评审不可用按暂时故障合同重试或等待，不能跳过。

### 版本、提交与交付

工具、检查与评审结果关联 task_id、目标版本、验收版本、成果版本和实际使用的能力快照。必需检查方法的实质变更也是验收版本变化；保留覆盖差异并独立复核。降低用户要求必须取得用户明确同意。

成功提交前检查当前执行身份、预期版本以及已接收输入处理位置。旧版本结果可以追溯，不能更新当前通过状态。已接收而尚未解释的纠偏输入不得被旧的完成提交越过；明确暂停或取消立即阻止新动作派发。

同一 task_id 只有一个逻辑终态；成功、最终失败和取消争用同一提交位置。回执丢失先读取原终态，不能换请求 ID 再生成一个。唯一终态事件同时提供可重建的经验和交付义务；经验提取先提交完整候选清单，逐项审核处置，父义务由全部条目结果重建，详见 00 的 R02、R09。

副本先验证和评审，再应用本任务所需改动到最终位置，核对期间变化并按影响复验。最终消费者仍找不到 Skill 就不能完成。清理在保留必要成果和证据后进行；正在等待的受管进程、用户原有文件、被指定保留的成果不是垃圾。

默认本地结果入口可满足交付；任务明确要求的发送或部署仍是必要义务。可选通知失败只补通知，不能重做已完成工作。

### 失败归因

保存原始 exit code、错误输出、基线与当前改动，再判断任务失败、环境阻碍或被中断。不得将某个退出码一律归为环境错误并从基准分母剔除。任务造成的导入或配置错误仍需修复；与本任务无关的已知基线问题单列并说明依据。

## 五、spawn 与只读协作

主子助手共用循环形状。子任务返回：结论、实际读取来源、相关文件、证据引用、未解决问题和完整轨迹入口。摘要有界，完整事件和必要内容留在 Journal/CAS，父助手可以下钻。

| 场景 | 首版规则 |
|---|---|
| 只读探索 | 可并行；共享读取位置和明确的版本。 |
| 独立评审 | 只读与受限检查；结果绑定被审对象，主助手修改后检查适用性。 |
| 修改 | 主助手执行；子助手不能借 shell、进程或 MCP 绕过只读。 |
| 多个候选并行编码 | 后续设计；每个候选独立环境，主助手选择、应用和验证。 |

深度 0→1→2，运行时检查 depth；depth=2 不能继续派生，可以自行完成受允许的调查或向父助手报告。扇出按任务需要选择，小任务不强制派发。兄弟独立形成结论、父助手汇总；冗余调查和 falsifier 是策略选项，不能成为固定工具顺序。

委派身份、重复问题的历史继承、父版本及控制变化、迟到结果和终态前子任务交接采用 00 R11 T5。深度限制不能替代同层去重和并发调度。2026-09-08 本轮只补合同及纯验证，不实现通用 spawn；现有主执行／独立复查的验收不替代完整子任务生命周期测试。

单任务内只读协作不能消除跨会话共享资源冲突。扩展目录、注册表和重叠工作区的写入归后台统一协调；记录资源身份和预期版本。

## 六、输入、后台进程与恢复

REPL/窗口是可重连客户端。首版单机后台拥有任务，统一持久化状态；关闭终端不结束正在运行的任务。电脑睡眠、关机或后台进程退出期间不能继续计算。

用户输入先持久化归属和事件，再处理语义；长工具调用期间仍能接收控制。取消能力取决于实际工具，不假定信号能撤销外部效果。旧 `SIGALRM` 只作源码线索，不能直接作为所有并发调用和后台控制的实现合同。

操作进程归任务管理，不归一次模型函数调用。等待、暂停、取消和终态分别决定资源处理；不能沿用返回即 cleanup 的 finally，也不能把所有进程标记 keep。PID、操作引用、输出、完成事件和进程归属要能重新核实。

每个长操作登记超时或最迟重新判断时点；到期根据阶段成果、工具语义和目标关联证据决定停止、恢复或有依据地延长。仅 PID 存活不能无限续期，详见 00 的 R08。

### 恢复合同

- 稳定 task_id 与每次 run_instance_id 分开；同机同版本恢复原目标、验收、待办、失败路径、成果和能力依赖。
- Journal/CAS 数据密钥持久保存并受控重新取得。旧进程内 InMemoryKeyProvider 不能承担跨重启解密。
- 恢复建立新的执行身份和有效执行权；读取历史不等于恢复旧进程的活跃权限，旧实例不能继续提交。
- 操作在效果发生前、部分发生后、效果完成但记录未提交时中断，分别按工具合同核实。可确认完成则接纳结果；部分完成则续接或修复；效果未知不能盲目重发。
- 不要求任意外部工具实现恰好一次或完整回滚，但每类实际接入工具必须说明如何查询、何时允许重试和何时等待用户。

### 批次 3 的准入、接续与调度

执行 00 C1—C8。完整执行描述在任务准入前保存并由同一 Journal 准入决议关联；重复提交按稳定身份与内容比对，不能随机创建另一会话。长模型/工具等待在状态短提交锁之外，控制输入仍能先持久受理。客户端断开不触发任务 finally 清理；状态和 attach 只读。

恢复先核实软件/配置、工作区、能力与权限，保留目标/验收的持久更新，处理所有更早未解释输入；原暂停/取消优先。新 run_instance/epoch 只拒绝迟到提交，仍须核实旧进程效果。RecoveryReady 后按当前状态继续，终态和不具备完整描述的遗留任务不会自动重跑。被中断的尝试按原绑定结算，不将服务中断计为业务失败，不清空既有停止与分歧计数。


2026-09-08 的 3B 语义细化：显式启动后台可自动接续具有完整兼容描述、已确认安全且原控制意图为 RUN 的任务；status/attach 不启动后台或接续。显式 resume 先持久受理有稳定幂等身份的有序继续意图，再由执行器处理；它只能覆盖更早 PAUSE，不能覆盖更晚 PAUSE 或任何 CANCEL，不修改目标/验收。纯恢复不默默解除暂停，取消和终态不重开。恢复验证不长期占用控制请求锁；Ready 提交与后续派发均复核当前输入前沿。按各任务保存的结构化环境身份验证，不能将启动后台时的另一个 workspace 当成任务环境。已持久的 cycle、preflight、检查/评审、私有协议引用及待处理输入按安全边界重建；不能仅放开旧执行身份断言后从 cycle=0 重跑。

新增准入、恢复和效果探测事件在协调器热投影、冷重放、上下文和只读状态读取中采用相同语义；不认识的版本明确停靠。首版的全局业务修改通道继续执行获权后最后核对及稳定交接。真正跨进程与故障点证据按 07 登记。

## 七、进展、停止与计数

**同一障碍连续四次有意义尝试仍无进展，进入卡住状态。** 按任务验收项和稳定障碍身份关联尝试；每次有实际操作或完成提案、结果与进展依据。

有意义进展可以是满足验收项、获得必要证据、排除关键原因或解除依赖。无目标关联的新文字、改名字或重复确认同一事实不算。正常下载轮询不算失败尝试；同一无证据完成提案反复提交不能逃过计数。

程序记录并核对可直接判定的事实；主助手解释语义和归属，存疑时定向复核。不得因为不同参数、batch 或 error label 就清零。计数更新、清零、恢复和人工改方向规则以 [00](00-本版生效规则与执行契约.md) 为准。

调查批次在派发前登记问题、有限动作和结束条件，结果齐备必须结算。不能不断追加重复读取使同一尝试永远不结束；需要继续时先结算，再创建有关联的新尝试。00 R11 T1 要求实际运行器在批次边界归还调度器，不能只在整个 run 返回后才创建结算记录；局部工作额度仅触发让出，不是全任务计数上限。成功但没有新证据的重复读取也纳入判定，真实等待和新页／新版本读取则按实际作用区分。

| 计数 | 条件与用途 |
|---|---|
| 行动无进展 | 同一障碍四次有效尝试，触发卡住报告。 |
| 评审分歧 | 相同分歧三次，集中展示证据和建议。 |
| 暂时故障 | 单次模型、工具或评审故障的独立重试合同，耗尽后等待或失败归因。 |
| 历史错误复发 | 结项经验依据，不在第三次自动停任务或自动发布永久规则。 |

测试趋势、重复 error_key、工具参数相同可以提供证据，不再各自保留“三次即终止”的旧分支。没有通用精确进度公式；探索不能只按失败测试数判断。

历史状态与证据按 00 R11 T2 判进展，恢复到已达到的旧水平不再次清零。复查采用 T3 的验收项／稳定问题及证据关联，不用固定 outcome-1 键混合所有非 PASS；格式、证据读取和服务故障有独立有限出口。T4 的内层结构化信号不能直接宣布任务失败。T6 的程序停止报告包含已验证完成、未验证部分改动、缺口、未知效果与恢复条件，读取或展示报告不启动模型，也不改变任务终态。

首版暂时调用故障默认初次失败后最多重试两次，可按调用配置调整；这是工程默认值，不是用户四次无进展的延伸。失败重启仍保留该逻辑调用的重试组，不无限另起 ID。

不默认用总轮数、费用或 token 判断任务失败。上下文到限先整理、缩减旧细节并保留索引；无法形成有效上下文时保存状态和明确阻碍，不丢任务。单次模型调用和工具操作需要超时、等待及恢复安排。

## 八、checkpoint 与任务投影

存储 checkpoint 是恢复基础，不能把 `turn + offset + preset + goal_ref` 宣称为完整任务恢复。任务投影需从有版本事件或已验证根对象重建，包含当前目标、验收、义务、操作、资源、能力依赖、进展计数和证据入口。

可保存从日志构建且可验证的投影快照，恢复后回放其后的事件；它不是独立事实权威。每轮不需要从事件 0 重放。完整消息、工具结果和失败轨迹可存 CAS，模型上下文只是当前表示。

保留 Journal 对完整提交、撕裂尾部和已提交字节损坏的区分。写入失败停止依赖该状态的新动作，不用内存假装持久成功。

## 九、preset

YAML 控制工具、system prompt、model 和允许派生角色；不能改写当前任务验收或赋予模型直接提交成功的权限。共同完成门按各任务合同执行，因此只读子任务也有合法完成路径。

```yaml
name: reviewer
model: <非主循环模型>
capability_profile: read_only_review
can_spawn: []
system_prompt: |
  根据当前要求、实际成果和原始证据独立判断。
  必要时请求程序运行受限检查。
```

`read_only_review` 必须展开为明确可读范围、允许动作和检查接口；仅移除 edit/write/str_replace 不合格。`extends` 使用显式 add/remove 与可验证合并，未知工具和模板变量启动时校验。动态能力激活也重新校验受影响 preset，不静默忽略缺失工具。

项目级同名 preset 整体覆盖全局，除非声明 extends。保留有用的旧角色 prompt，但按真实用途选择，不为保留 12 个名字恢复固定管线。

## 十、工具与 Skill

| 能力 | 合同 |
|---|---|
| 精确替换 | old_str 唯一匹配；零／多匹配区分错误，可提供近似位置；不把显示行号写回文本；修改后文件视图失效。 |
| create/edit | 创建已存在路径失败；编辑保留已有内容，不能默默变成整文件覆盖。 |
| read/grep | 支持 offset/limit、rg 和可恢复证据引用，工具返回本身有大小边界。 |
| shell/进程 | 根据任务明确工作位置、可写范围、网络、执行程序和资源生命周期，支持真实依赖安装与验证。 |
| 外部安装 | 指定扩展目录、环境和配置可以成为授权目标；不能一律以“worktree 外”拒绝。 |
| 检查请求 | 声明被检查版本、命令／输入、读写和网络范围、临时输出及结果证据。 |
| Skill | 通用 SKILL.md 基础格式与旧格式适配；简要目录发现、按需阅读全文及资源、通过工具实际使用。 |

能力安装、候选试用、默认发布和业务验收分别记录。安装登记只新增已安装版本；将目录、说明、schema、资源、依赖环境和执行器构建为完整候选快照，此时不修改普通新会话默认。

仅当前任务或指定验证会话显式选用候选，从真实 Sitina 入口、稳定安装位置和候选依赖运行最小有效用例。这个验证复用现有会话和版本目录，不引入多助手并行候选平台。候选准备及试用不能原地破坏旧快照所依赖的内容或环境；评审检查仍遵守 R06，不得顺手改启用配置修复方案。

试用结果失败、未知或缺少必要凭据时不发布，原默认保持不变。主助手根据实际证据修复，形成新候选快照并重新试用；不能用旧候选的成功记录批准修复后的新内容。普通输入错误、外部服务故障或缺凭据不直接等于能力回归，但已知 handler 绑定或依赖不完整必须修复，不能推给用户或冒称能力可用。

最小有效用例通过后，按 publication_id、候选快照、原默认发布身份和预期当前指针条件提交默认发布，并遵守共享登记 generation 检查；发布时重新核对任务控制状态，发布前取消必须阻止迟到试用结果发布。共享能力 Journal 的发布决议同时记录默认变更、候选关联和普通新会话检查义务；registry 是带 applied_frontier 的可重建投影，普通默认读取先追平至当次权威读取位置；检查及失败待归因关联本次发布，在取消或重启后仍按有限处理规则接续。发布后在不显式指定候选的普通新会话再次验证。实际默认加载和业务成果未满足时不能宣布安装任务成功。

发布后确认该能力回归，持久记录按 publication_id 限定、绑定快照与失败条件的隔离和默认处理义务；扩大到其他发布须有独立依据，不能按同名版本连带禁用后来发布。只有当前默认仍属于本次 publication_id 与快照，才可条件恢复仍可用的旧默认；恢复旧快照也创建新的 publication_id，没有可用旧版则用新变更身份记录未启用，不能倒拨旧身份。后来发布不能被覆盖。普通业务取消不自动撤回已发布的健康安装；但发布检查、待归因和确认回归后的处理义务在取消、退出或重启后仍要接续，不能依赖任务调用栈临时补救。

每次请求和操作记录实际快照；显式试用标明候选选择，使用已发布能力时关联实际 publication_id。候选发布时保存候选到 publication_id 的关系，原任务后续派发不得以候选选择绕开同一已知故障的隔离。活动任务仅按其明确的安装／更新切换；旧请求返回仍使用旧绑定或明确拒绝后重规划，不能用新 schema 解释旧参数。后台经验整理不能悄悄修改活动任务依赖。精确条件和义务去重见 00 的 R07。

工作目录不是沙箱。保留实际效果边界，但不能把旧 deny-network/deny-fork profile 平移称为自由 shell 已完成；当前 Controller 命令与环境约束必须实测。computer use 不属于本版工具要求。

## 十一、可观测性

事件记录输入、状态、操作、原始结果、版本、证据、进展依据和终态义务。人类日志和指标从结构化记录渲染，不建立新的事实权威。默认展示目标、完成项、剩余义务、当前动作和阻碍；细节可下钻。

记录主循环及子任务轮数、耗时、token、重试、接管、错误复发和完成提案与事实冲突。指标服务诊断，不以固定工具顺序或内部思维链验收。实现检查与正式产品验收见 [04](04-实施步骤.md) 和 [07](07-基准规范.md)。
