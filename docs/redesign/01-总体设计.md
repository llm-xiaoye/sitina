## 一、目标与非目标

### 目标

面向个人的 Loop Agent，完成代码修改与验证、只读调查审查、需要多次试错的长期任务。代表性端到端任务是获取 GitHub 项目或 Skill、安装依赖、部署到实际 Sitina 消费位置、当前任务正确调用并产生所需成果、新会话仍可使用。

**任务完成度、稳定性、人工接管次数和耗时优先。** 不默认设置全任务费用、token 或总轮数上限；token 与轮数保留为诊断指标。单次调用超时、上下文容量和无进展处理是不同约束。

首版必须做好：

1. 实际结果反馈驱动的循环，模型提出完成后由程序按当前任务合同确认。
2. 任务目标、约束、验收、失败路径、未完成义务的持久连续性，以及可用的项目经验与明确个人偏好。
3. 关闭终端后后台继续；同机同版本重启恢复任务，不要求用户重新描述目标。
4. 第三方 Skill 的发现、加载、使用和能力版本刷新，采用通用 Agent Skills 基础格式并兼容原格式。
5. 修改和安装交付前的独立只读评审，以及原始证据可下钻。

长期任务和记忆不能延期到“以后优化”。允许延期的能力必须说明当前能做什么、以后加什么、如何接入，见[能力边界与路线](/Users/moss/Documents/ChatGPT/sitinaRedesign/Sitina能力边界与后续扩展路线.md)。

### 非目标与后续范围

- 多租户、企业部署、高并发和合规审计平台。
- Linux 支持；执行边界可保留接口，首版只支持 macOS。
- 自主找活、任意外部条件的跨天定时监控。
- 多个助手同时编写候选方案；保留[后续设计](/Users/moss/Documents/ChatGPT/sitinaRedesign/后续设计-多个助手同时尝试方案.md)。
- **computer use 暂缓。** 本轮不展开其技术方案，不作为首版验收要求；历史桌面实现设想不再是当前交付承诺。
- 默认费用优化或自动降级模型。

旧稿关于不同产品能力、某个榜单的 token 差距与“准确率只由模型决定”的断言，仅保留在历史快照中。是否改进 Sitina 由本系统的真实任务结果判断。

## 二、架构

### 2.1 一个循环内核，任务状态由单机后台管理

`AgentLoop(tools, model, preset, task_context, depth)` 可复用于主助手和只读子助手。`spawn` 创建子循环，结果作为父循环的工具结果返回；模型按需要选择拆解、工具、调查和实现策略。

首版单机后台统一接收输入、提交任务状态和管理进程。每个会话同时只有一个活动任务；不同会话可保留独立任务。共享扩展目录、注册表或同一项目的修改通过统一资源归属与版本检查处理，不能从“子助手只读”推断所有冲突都不存在。

2026-09-08 终止机制补强采用 `sitina-termination-v1`，规范入口为 00 R11 的 T1—T7。内层运行器在已登记的有限调查批次结束或需要让出时交还结果，由任务状态与调度统一结算；进展核对历史有效证据，复查按稳定问题计数。停止报告由程序生成，模型服务不可用也能交付已完成部分与明确阻碍。通用只读委派的父子身份、去重、取消传播与交接目前补齐接入合同，不据此声明真实子任务调度已完成。

主助手负责修改，子助手负责只读调查与审查。只读子任务可以并行，默认小规模派发，递归深度最多 2（0→1→2）；小任务不需要制造子任务。各子任务保留独立来源和完整轨迹引用，父助手负责整体验收。

复用现有 `AutonomousRuntime` 的真实工具反馈机制。正式 Forge 已有工具循环，执行桥已有有限验证返工；缺口是任务级合同和入口统一，不能只根据 `AgentRunner` 的接口判定整个系统缺少循环。

### 2.1.1 一个后台，五个内部代码模块

以下划分是阶段 4 采用的实现边界，不是五位 Agent 或五套常驻服务。对外仍是同一个后台和可重连窗口；可复用现有代码，不先按表机械搬迁文件。

| 代码模块 | 负责什么 | 向谁交结果 |
|---|---|---|
| 任务状态与调度 | 接收持久输入、安排动作、资源归属、恢复与条件提交 | 唯一提交入口；调用其余模块后接纳结果 |
| Agent 运行器 | 调用主模型，按需创建调查、标准预检与独立评审实例 | 返回行动／判断提案，不直接写任务终态 |
| 工具与进程执行 | 执行真实操作和检查，保存输出、核实未知效果、管理进程 | 返回操作证据和效果状态 |
| 验证 | 管理验收条目及版本、证据适用性、检查与必要独立复查 | 复用执行模块运行检查、运行器调用评审；返回通过依据或缺口 |
| 上下文与记忆 | 生成有界资料、历史查询、结项经验提取审核与索引 | 从持久记录读；发布候选和义务结果仍回唯一入口 |

Journal/CAS 是共享存储基础，投影与索引可以重建。验证不另造执行器，记忆不维护第二份任务真相；能力目录、说明、schema 和执行绑定仍按同一快照装配。唯一任务业务循环连接这些模块；模型网络请求、长命令和审核均不占住状态提交锁。

首版一次推进一个修改执行段，可在保存且静止的边界切换任务；只读与模型计算可并行。等待输入或稳定暂停释放可释放占用，恢复先取得通道及范围、再做最后一次相关前提核对；在途或已派发待启动操作未解决不能提前放行。细节以 00 R05 为准。

### 2.2 任务状态与完成

| 状态或事件 | 行为 | 是否完成 |
|---|---|---|
| 有未完成要求和可执行步骤 | 继续循环 | 否 |
| 等待具体工具操作或评审 | 保存操作引用，事件到达后继续 | 否 |
| 等待用户信息 | 保存问题、已完成内容和恢复入口 | 否 |
| 同一障碍四次有效尝试无进展 | 保存阻碍和证据，等待新信息或方向 | 否 |
| 用户暂停 | 停止派发新动作，按合同处理现有操作 | 否 |
| 用户取消 | 停止推进，保留已发生效果及取消记录 | 否 |
| 当前条件不可恢复的错误 | 记录最终失败与未完成部分 | 否 |
| 当前必需要求、评审与交付全部满足 | 程序提交 `SUCCEEDED` | 是 |

旧稿的 `INTERRUPTED` 不再是所有插话的统一终态；熔断是处理原因，不替代等待、暂停、取消或最终失败的区分。

需要用户决定时，报告必须包含：已完成部分、明确阻碍、推荐选择、推荐原因、每个选项的利弊，以及如何继续。不重复请求已授权的普通操作。

### 2.3 三层验证

| 层 | 责任 |
|---|---|
| 执行中 | 工具由程序实际执行，返回原始输出和效果；主助手根据反馈修正 |
| 程序完成检查 | 逐项核对当前任务要求、适用证据、成果版本、未完成操作与交付条件 |
| 独立评审 | 修改、安装等任务交付前，由一个非主循环模型读取真实要求、成果与原始证据 |

模型的完成宣称只是提案。程序可直接判定的数据失败，不能被模型投票改成成功；内容是否符合用户要求仍需相应的内容检查和评审，程序不能仅靠字段齐全证明任意语义正确。

不同任务使用不同依据：代码按行为和相关检查；只读调查按来源和结论；文档、图形成果按实际内容；安装按实际消费位置的加载和使用；现状已满足时允许有证据的无修改结果。**不存在所有任务统一 diff 非空或测试计数的门槛。**

评审可以读取、搜索和申请检查；实际可写范围由程序控制，不能仅删除 edit/write 就向评审开放任意 shell。评审返回必须修项、缺证据、无阻断或可选建议。可选建议不扩大任务。相同评审分歧反复三次单独处理，不能混入四次行动无进展计数。

检查结果绑定任务、目标、验收和成果版本。成功提交前核对已接收输入和当前版本；过时结论保留追溯，但不得通过新要求。副本成果先验证和评审，再应用到最终位置并核实有效，最后清理不再需要的任务临时资源。

### 2.4 记忆与长期任务

- Journal 记录不可变事件，是经历权威，不自动证明事件中的 claim 为真。
- 当前任务记录在运行中持续持久化；每轮提供目标、硬约束、未解阻碍、近期行动和精简索引，详细历史可按需读取。
- 成功、最终失败和取消以唯一逻辑终态事件作为 episode／经验整理义务来源；启动时可补建待办，暂停不急于形成最终教训。
- 结项后独立处理候选提取、审核、去重、替代和归档。语义整理不阻任务成果交付；调用故障可重试，审核拒绝或无需形成经验可以结清，不能重新执行已经完成的任务。
- 新任务记录审核经验视图，新增结项经验默认供后续新任务使用；已撤销错误经验仍需及时排除。原始历史可作为带状态的证据查询，不能被悄悄升级为事实或系统指令。审核后的发布复核相关记忆版本，详见 00 R09。
- 新的强制规则经用户批准后用于新任务；后台整理不能静默替换活动任务正在使用的 Skill 或规则版本。

持久保留不等于每轮注入全量。记忆有效集与上下文有范围，历史物理存储可能继续增长；可追溯归档、失效和按需读取共同控制使用负担。

r4 进一步固定两处提交边界：共享能力发布以 Journal 决议同时确定逻辑默认、候选关联和检查义务，registry 仅为带提交位置的投影，默认读取必须追平到本次读取位置；结项经验先持久提交完整候选清单，再逐项审核处置，所有条目有最终处置才结清父义务。它们复用原有写入口，不新增角色或服务。

### 2.5 模型决定策略，程序落实合同

主助手结合用户原话和事实拟定任务验收条目、选择工作位置和方法。复杂修改／安装任务可由既有独立评审预检标准。程序登记当前有效版本，执行操作、保存实际结果、处理资源与状态提交。

用户请求中的“安装”“修改”“完成”等关键词不能直接触发路由、写权限、隔离选择或成功。关键词可以帮助发现候选 Skill，最终相关性和动作由助手结合完整语义判断。来自网页、仓库和 Skill 的内容不能成为新的用户任务。

### 2.6 批次 3 的后台连续性接线

连续性合同为 `sitina-continuity-v1`，以 00 R03 C1—C8 为准。一个后台持有唯一状态写入口、任务队列和执行器；CLI 是可断开和重连的客户端。任务完整执行描述与准入关联先持久提交才返回接受回执；重发同一提交返回原任务。状态读取和 attach 不恢复执行，显式恢复沿原 task_id 检查历史、现场和当前控制意图。

后台重启建立新执行代次，先核实旧命令与未知效果、保留输入和计数，再继续原任务。第一阶段只接通无在途效果的安全边界，随后接通现有文件、检查和长命令。新增宿主和恢复器属于现有五模块内部代码，不增加“管家”或新的模型决策层。3A—3D 已通过最终 388 项组合门禁及两例有限真实入口验收；已接入文件、检查与受限 shell 的恢复范围见本章顶部验收入口。状态读取不启动后台；启动后台可自动接续已核实安全的 RUN 任务，显式继续使用持久有序意图解除更早暂停，不能覆盖更晚暂停或任何取消。

## 三、使用形态

```text
用户：安装指定 Skill，并按要求生成一张图。
主助手：调查来源与依赖，形成验收条目和工作计划。
程序：登记安装操作，在任务允许的实际位置执行。
主助手：根据失败证据修复依赖；有进展就继续。
程序：构建完整候选快照，仅当前任务／指定验证会话选用。
主助手：从真实入口和稳定安装位置运行最小有效用例，检查实际内容。
程序：试用通过后按发布身份和预期默认指针条件发布。
主助手：在不指定候选的普通新会话中验证，再完成用户所需成果。
独立评审：核对当前要求、实际成果和使用证据。
程序：验证最终消费位置与新会话可用，提交成功和后处理义务。
后台：整理 episode 和候选经验，审核、去重并发布有效版本。
用户：顺便再做另一张图。
程序：建立关联新任务，复用已确认的背景与能力。
```

候选首次试用失败、结果未知或缺少凭据时不发布默认，修复产生新快照后重验。发布后确认能力回归，持久记录隔离和默认处理义务；仅当当前默认仍属于本次发布身份及快照时恢复可用旧默认，无可用旧版则明确未启用，不能覆盖后来发布。业务取消不自动撤回健康安装，但不免除已经确认回归的处理义务，详见 00 的 R07。

活动任务期间的纠偏形成新的有效目标版本，原始请求继续保留。状态询问不改变目标。窗口关闭不终止后台任务；进程退出或机器重启后按恢复合同核实旧操作，再接续同一任务。

## 五、必须由程序保证的约束

- 输入先持久化，动作派发与成功提交检查当前任务版本及执行身份。
- 必要验收项不能由助手为过门而降低；实质检查方法变化也要版本化及复核。
- 四次有效尝试、三次同一评审分歧、暂时故障分别计数；不能改名清零。
- 持久数据密钥可重新取得，恢复建立新执行身份；旧进程不能继续提交当前任务状态。
- 能力目录、说明、schema、依赖与实际执行器关联同一候选快照；实际试用通过后条件发布默认，活动任务记录快照和发布身份。确认回归后的处理义务持久保留，不覆盖后来发布。
- Journal 写入失败停止依赖该状态的新动作，不用内存伪造成功。
- CAS 完整性和 canonical bytes 校验保留在相关证据边界，不能代替事实与内容验证。

## 六、主要实施风险

| 风险 | 处理 |
|---|---|
| 代码已存在却未接正式入口 | 以真实 CLI 的三类任务及安装用例验证调用链。 |
| 旧证据通过新目标 | 目标、验收、成果版本和输入位置在提交前复核。 |
| 恢复只恢复存储，没有恢复任务 | 稳定 task_id、数据密钥、新执行身份、操作效果核实共同验收。 |
| 长任务上下文不断增长 | 有界当前表示、失败索引、按需查询及压缩恢复用例。 |
| 经验积累或误泛化 | 审核、范围、去重、替代、归档、撤销以及真实收益比较。 |
| 安装成功但当前 Sitina 不能用 | 候选先真实试用，之后条件发布默认并以普通新会话复验；失败或确认回归按 R07 处理。 |
| 大量基础设施阻挡首个可用版本 | 少量真实用例起步，实施者准备验收材料，用户判断产品结果。 |

## 七、迁移原则

新路径接入并通过对应真实用例后，再退役旧路径。保留 Journal/CAS、真实工具执行、独立重算和反目标漂移原则；不要为保留旧对象而复制完整固定角色协议。修改依赖边界时重建受影响证据，旧运行身份不得用于宣布新源码通过。具体步骤见 [04](04-实施步骤.md)，依赖见 [05](05-危险区地图.md)。
