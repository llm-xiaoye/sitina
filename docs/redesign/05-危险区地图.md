## 一、源码身份与路径清单是两类依赖

旧稿列出的 21 路径清单位于 `true_multi_agent_runtime.py` 的 source_paths 枚举，包含 legacy/fence、true_multi_agent、conversation 相关文件和配置。

已核实：live 分支逐项打开文件计算物理哈希，路径缺失会抛 `FileNotFoundError`；offline 分支先判断 `is_file()`，可跳过缺失文件。FAST 与 MULTI 的 Provider activation 都涉及这条路径。offline 检查通过不能证明删除后 live 可以激活。

另一条是 Code Mode runtime source manifest，涵盖 config 顶层与 core/sitina 的 Python 文件，Authority host 重新打开 Journal/CAS 时会复核。未执行过的模块仍可能参与身份计算。启动前修改成为新基线，长存活会话中修改可能触发身份漂移。

因此旧“改内容无事”的说法只适用于某个哈希记录步骤，不能推广到正式运行时。修改 Sitina 自身应在独立开发目录形成候选，当前实例固定版本，验收后启动新版本。

| 操作 | 必须检查 |
|---|---|
| 改内容 | 当前运行是否绑定旧 source manifest；受影响证据与消费者是否需重建。 |
| 移动／删除 | import、枚举清单、manifest、配置、动态入口和脚本引用。 |
| 新运行 | 用当前源码和配置建立新身份，不复用旧活跃 authority。 |

迁移顺序：先明确替代路径和引用闭包 → 同步导入／配置／身份清单 → 删除退役文件 → 新实例 live 激活 → 真实任务验证。不能只改 21 路径元组就认定所有依赖已解除。

依据：[source manifest 生成](/Users/moss/SitinaHub/core/sitina/orchestrator/code_mode_runtime.py:233)、[host 复核](/Users/moss/SitinaHub/scripts/code_mode_authority_host.py:298)、[阶段 2 核实](/Users/moss/Documents/ChatGPT/sitinaRedesign/阶段2-重设计理解与代码差距分析.md:201)。

## 三、evidence 与存储的真实依赖

### evidence 不能按“生产零调用”直接删除

`execution_verification` 顶层导入 `execution_sandbox`，后者顶层导入 `evidence.isolation_provider.ReplayIsolationProvider`；旧 qualification 也使用该类。正式 Tester 可能走新 worker 分支，但未执行旧业务分支不等于没有 import 依赖。

| CAS crypto/local/gc | 多处写入和 Journal 引用闭包依赖；不能把加密文件视为可直接删除的额外复杂度。 |

## 四、真实执行边界与进程归属

正式 Forge 注入 Controller worker executor，Tester 也优先走该 worker。实际 profile 来自 `_code_mode_sandbox_profile`，不是单纯使用旧 `frozen_sandbox_profile`。当前允许执行程序、网络、命令校验及环境限制决定 make、包安装、git 和通用测试能否运行。

不能说模型执行完全没有 OS 边界，也不能把旧 deny-network/deny-fork profile 平移称为“自由 shell 已做好”。改造应验证用户任务实际需要的执行程序、工作目录、环境、网络和可写位置。

依据：[worker 注入](/Users/moss/SitinaHub/core/sitina/orchestrator/true_multi_agent.py:10555)、[实际 profile](/Users/moss/SitinaHub/core/sitina/orchestrator/code_mode_controller.py:146)、[worker 命令限制](/Users/moss/SitinaHub/scripts/code_mode_worker.py:279)。

| 边界 | 容易误判的地方 | 本版要求 |
|---|---|---|
| 评审只读 | 移除 edit 后仍可通过 shell/MCP 改成果。 | 显式只读效果范围；检查通过程序在指定环境执行。 |
| 安装 | 真实成果位于扩展目录／环境，项目 diff 看不见。 | 验证实际消费位置和版本，写入范围由任务合同指定。 |
| 等待 | 内嵌循环 return 的 finally 清理了仍在运行的下载。 | 进程归任务；等待、暂停、取消、终态分别处理。 |
| 效果未知 | 日志没有完成事件就再次执行外部操作。 | 按工具合同核实效果，部分完成续接或修复，不盲目重发。 |
| 共享注册表 | 单次文件替换和随后 audit 是两次写，锁不使它们原子提交；默认读取还有多次读取。 | 共享 Journal 决议为权威，registry 投影有位置与单写入口，普通默认读取追平并使用同一视图。 |

## 五、恢复与能力刷新

### 存储恢复不等于任务续跑

正式 chat 目前创建新的 Code Mode session instance，并使用进程内 KeyProvider。旧 checkpoint 主要服务存储和 authority，不能只调用 cmd_resume 就承诺新 Loop 完整恢复。

本版需要稳定 task_id、可重建任务投影、持久数据密钥和新的 run_instance_id／执行权；恢复核实环境、旧操作和资源。旧进程不能继续向当前任务提交。

### 已安装不等于已激活和实际可用

现有 Skill 选择与工具 schema 在任务开始生成，内嵌循环继续使用传入 schema。安装器已有 staging 和 active 版本，但安装时即改变 active；不能沿用该默认发布时机，再只为当前任务保留内存中的旧快照。

本版先登记已安装内容并构建完整候选，保留旧内容及依赖。仅当前任务或指定验证会话显式使用候选，从真实 Sitina 入口和稳定安装位置完成最小有效试用；通过后才按 publication_id、快照及预期原默认发布身份条件发布，再由不指定候选的普通新会话验证默认发现和实际调用。构建、首次使用失败或效果未知均不改变原默认；普通输入、凭据或外部故障不直接证明能力回归。

发布后确认回归，先持久隔离受影响发布／快照并登记默认处理义务。当前默认仍属于本次发布且旧运行条件可用才恢复；无可用旧版则停用，后来发布不得被旧结果覆盖。取消和重启不丢处理义务，旧请求也不得用新 schema 解释。精确条件见 [00 的 R07](00-本版生效规则与执行契约.md)；通用 Skill 格式、默认解析、真实调用和成果验收仍需分别接通。

r4 明确不能只改 _save_registry：install_skill 当前先保存 registry 再追加 audit，skills 与 active_plugins 又分别读取登记。新实现须同时迁移所有默认变更与默认读取，Journal 决议一次包含默认、候选关联和检查义务，投影落后可恢复；详见 00 R07。当前源码仅做静态核对，不代表已经复现新分支故障。

现有工具 schema 的八类类型不是 Agent Skills 格式兼容的证明。已装外部 MCP 更不等于 computer use 已贯通；**computer use 本版暂缓**。

依据：[任务开始能力选择](/Users/moss/SitinaHub/core/sitina/extensions/runtime.py:816)、[后续模型调用](/Users/moss/SitinaHub/core/sitina/extensions/runtime.py:976)、[安装 staging](/Users/moss/SitinaHub/core/sitina/extensions/manager.py:271)。

## 六、输出协议与 Provider

保留小增量工具调用和原始内容校验。旧大 JSON 输出及截断修复只能作为历史失败线索；新实现不能把未生成的内容拼接成“已验证模型结果”。小输出降低风险，但不能宣称所有截断问题自动消失。

Provider adapter 负责 wire format 和工具调用差异，核心使用一致的 intent。只清除模型字面量不足以证明 Provider 中立；要检查真实调用、结果和失败恢复。原生 tool-call 与实际支持的文本 fallback 分别验证，fallback 不得伪造成功。

profile 文件名不代表实际模型，读取实际配置和响应元数据记录身份。历史文件名、模型和中转端点不作为当前承诺。不要因为文档清理顺便轮换凭据、打印密钥或更换用户模型。

## 七、循环和验收容易复发的混淆

| 混淆 | 本版处理 |
|---|---|
| 删 `max_execution_turns:5` 就没上限 | Forge 会回退 16，Runtime 默认还有 50；新路径须处理机制及全部回退。 |
| 三个相同工具调用就必然空转 | 工具相同是证据，不是终止合同；同一障碍四次有效尝试无进展，正常轮询除外。 |
| 预算可以替代或必须叠加总轮数上限 | 本版无默认总费用／总轮数门，使用进展、评审分歧和单次故障合同。 |
| 只需测试数下降 | 探索可通过新证据、排除原因或解除依赖推进。 |
| 程序记录了通过就证明符合要求 | 必须核实当前目标、验收、成果与证据版本，内容仍需相应检查。 |
| 相同 hash 就是真实 | 完整性不等于真实性；保留实际结果与独立观察。 |
| 最新记录胜出 | 事实冲突重新取证；用户纠偏产生新目标版本。 |
| 四次失败就自动生成永久禁止 | 四次是当前阻碍处理；结项经验审核和强制规则批准另走流程。 |

## 八、按真实入口执行迁移

关键原则是：**业务未调用、模块未加载、文件未参与身份计算、产品未验收，是四种不同结论。** 为每项退役记录当前入口、调用或导入边界、替代点和真实验证；不要用全库关键词零命中代替产品可用。

初始 state 目录为空的旧判断不能覆盖正式会话子目录；原有 scratch 泄漏应按任务归属处理，不能直接删除用户成果或在途进程。首版工具链已有 bundled Python，锁定依赖仍需独立验证，不与“没有解释器”混同。
