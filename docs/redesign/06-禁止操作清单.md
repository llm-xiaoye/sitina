## 一、用户内容、当前证据与产品验收

1. 禁止把旧 source、manifest、artifact、运行身份、缓存或报告当作新版本的通过证据。核对实际消费者和内容版本。
2. 仍保留旧 successor/coordinator 路径时，禁止只更新其中一个而继续使用不一致对象。新 Loop 不为维持旧名词而重新制造这些对象。
3. 同一提交依赖的源码、配置、任务目标、验收、成果和能力版本必须对应；不匹配结果只作历史追溯，不能更新当前通过状态。
4. 禁止把未经适用性核对的旧成果冒充当前结果、篡改哈希，或把 producer 自报当独立观察。按 00 R02 显式核对后可以复用旧证据；完整性只证明内容未变，不证明任务完成。
5. 禁止把历史记录、旧 PASS 或未执行分支当当前事实。必须区分代码存在、已加载、实际执行和正式产品验收。
6. 禁止只凭文件存在、日志绿色、import 成功、进程启动、工具注册或 exit 0 宣布任务成功。
7. 禁止为过门删除评分夹具、降低用户要求或放宽必要检查。正常开发所需的项目测试修改按任务范围进行，不自动等同于作弊；固定评分依据不能由被测对象改写。
8. 禁止自动恢复旧进程的活跃 authority。历史数据使用持久数据密钥读取，当前执行建立新身份及有效执行权。
9. 禁止在依赖和证据影响范围尚不明确时宣布该部分通过；保存缺口并继续核实，必要阻碍如实报告。
10. 禁止用 reset --hard、checkout 覆盖、清空真实输出目录等方式毁掉用户已有未提交或未跟踪内容来制造干净环境。
11. 禁止以单元测试、mock、静态检查、保护性拒绝或 Provider 连通代替真实 CLI 的目标任务验收。
12. 禁止把未完成、等待或失败包装成产品成功。按任务类型检查真实结果与必要独立评审；**不得给所有任务强制非空 diff 或测试计数**。
13. 禁止夹具偷偷简化用户真实状态。需要的 unborn Git、未提交／untracked 内容、环境、正式消费者和重连路径应在对应案例中保留。

## 二、循环、状态与经验

14. 禁止按用户 goal 文本的子串直接决定执行、隔离、权限或成功。候选 Skill 发现可使用关键词线索，实际策略由助手结合完整语义与证据选择。
15. 禁止让模型自述直接提交终态。程序核对当前要求、证据、成果和输入位置；同一 task 只能有一个逻辑终态，回执丢失先查原提交。
16. 禁止把“没有 edit/write/str_replace”当只读实现。评审不能借 shell、进程、网络或 MCP 改成果；检查在声明的范围执行并返回原始结果。
17. 禁止 Journal 写失败后用内存假装持久成功。停止依赖该状态的新动作，保留可恢复的实际成果。
18. 禁止未完成替代接线就拆除旧主路径。先让相应真实任务在新路径通过，再迁移依赖、切流和退役；不把旧巨型文件作为所有新逻辑的归宿。
19. 禁止为保留固定角色名称或协议数量增加无功能价值的流水线；任务状态、版本和操作恢复合同不属于可以省略的“装饰协议”。
20. 禁止提取者直接写 accepted/authoritative。只提交候选，由独立审核和程序发布当前有效版本。
21. 禁止把经验、网页或 Skill 正文升级为用户任务、系统指令或新的强制权限规则。强制规则经用户批准后用于新任务。
22. 禁止以最后写入时间自动裁决客观冲突；重新取证或隔离。用户纠偏更新有效目标，不受旧工具观察覆盖。
23. 禁止改写历史事件；冲突、撤销、替代和新要求以新事件记录，可重建投影允许更新。
24. **禁止丢失结项整理义务、发布未审核经验或因整理失败重做已完成任务。** 本版要求异步结项整理；终态事件可重建待办。审核拒绝或无值得提炼内容可以结清，不无限重复提案。
25. 禁止把某个 Provider 的业务假设写进通用 Loop。adapter 处理实际 wire format，fallback 不得生成虚假成功。

## 三、比较、操作与范围

26. 身份、签名、重放和证据边界需要字节语义时，禁止宽松 JSON/dict 相等代替 canonical bytes 校验；保留类型区别，不把字段齐全当真实。
27. 禁止因“幂等命中”跳过新状态提交的当前条件。已存在终态时核实任务和命令归属，返回原逻辑提交及成果，不再创建终态，也不把它当作后续新任务通过；操作重试依据实际效果合同。
28. 禁止以哈希不变替代事实和内容检查；任务成果仍需适用证据。
29. 禁止将主助手映射或总结当作实际执行证据。由程序执行或重新观察，同时保留原始结果及其版本。
30. 禁止把 worktree 当执行沙箱。工作位置、可读写范围、网络和进程生命周期必须明确；已授权安装位置可以在项目之外。
31. 禁止把创建悄悄变成覆盖已有文件。创建与编辑的实际行为必须清楚，精确修改核对匹配及视图版本。
32. 禁止把 computer use 加入本版交付或验收。用户已要求暂缓，历史桌面拒绝清单和截图方案不构成本轮待执行计划。
33. 禁止把“外部 MCP 已安装”或候选能构建当完整能力已通。Skill 先在当前任务／指定验证会话经真实入口试用，通过后才条件发布默认，再由不指定候选的普通新会话实际调用；失败或未知候选不得成为默认。确认发布回归时持久隔离并执行 R07 的条件撤回／停用，禁止覆盖后来发布、虚构可用旧版或因取消／重启丢失处理义务。普通输入、凭据或外部故障不得仅凭报错直接判回归；computer use 后续重新确定方案。

## 四、实施纪律

34. 禁止使用漂移前的评审或检查批准漂移后的对象。绑定目标、验收、成果和内容身份；commit 是固定快照的一种方法，不是所有任务唯一方法。
35. 禁止以组件绿色代替产品验收；也不为形式新增通用攻击测试或无新理由反复全量测试。完成相关真实场景和必要回归即可。
36. 禁止用保留集指导同一轮调参并仍把它当独立评估；少量真实用例起步，后续逐步扩充。
37. 禁止降低门槛掩盖失败，也禁止只删除 `max_execution_turns:5` 却留下 16/50 等回退限制。新路径无默认全任务费用／总轮数门，配置和包装器须同步。
38. 禁止同一障碍换名字、参数包装、batch 或 attempt ID 清零；按四次有效尝试计数。三次同一评审分歧、暂时调用故障重试分别处理；未结算调查批次不能无限追加重复读取。
    本次补强同时禁止：用成功重复读取延长未登记或不结算的调查；退步后恢复旧水平反复清零；把不同复查问题或格式／读取错误混成同一分歧；内层三次错误独立宣告任务失败；以重新委派清空历史；为停止总结再强制调用不可用模型；把部分改动当已验收成果；将纯委派合同测试称为真实多 Agent 生命周期已接入。具体以 00 R11 T1—T7 为准。
39. 禁止在退役文件的同一批次夹带无关新功能。先明确依赖和替代行为，保留可回滚版本，再删除旧路径。

- 需要重建的证据，不用历史 PASS 或无关分支测试替代。

这份核对是实施记录，不要求用户为每个工程选择批准一次。必要询问必须说明已完成内容、明确阻碍、推荐理由和各方案利弊。

## 六、PASS 前的实际证据

本版新 Loop 的通过以 00 的当前任务合同为准：有效目标与验收、被检查成果、能力快照、实际操作、必要评审、未完成义务和交付状态对应；程序在当前执行权下条件提交。

旧 source=manifest=artifact=successor/coordinator 等式，仅适用于仍保留的旧路径。新架构不得为凑等式恢复无关对象，也不能因此忽略其真实源码身份依赖。

代码案例保存适用测试的实际执行与计数；只读案例保存来源和结论；安装案例保存候选快照、真实入口试用、默认发布身份及普通新会话实际使用，已确认回归还要保留隔离与条件处理记录；恢复案例保存旧操作核实和新执行身份。用例类型决定所需证据，不要求每种情况都有 diff。

## 七、验证与修复顺序

1. 做与变更相称的定向检查，排除明显实现错误。
2. 从正式 CLI 完成对应真实任务，核对 Provider、工具、结果与终态。
3. 验证本次承诺涉及的纠偏、恢复、等待或版本冲突场景；不扩大为通用安全项目。
4. 完成受影响的回归；只有新问题或新改动才扩大、重复测试。
5. 对发现的失败保留最小证据，标记受影响结论过时，修复同一依赖链并重建相应验证。

r4 补充：不得以排队前检查批准获权后的旧写入；不得把 registry 与 audit 两次写入冒充一次发布；不得以单条经验发布结清尚有候选未处理的父义务；不得仅凭 spec_version 声明全部合同通过。已有校准须包含正确替代，不以参考图像素相同作为唯一答案。

普通改动在现有目录或副本中的选择服从任务和已有内容；取消不是回滚，恢复不是重复发送，等待不是清理许可。有关进程、效果未知、经验义务和能力激活的精确条件直接引用 [00](00-本版生效规则与执行契约.md)。
